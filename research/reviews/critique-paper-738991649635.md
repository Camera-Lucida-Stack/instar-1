The headline numbers in C1–C5 match the results files. The paper's interpretive weight, however, rests on points that are asserted rather than demonstrated. First, the claimed mechanism, that the optimiser stops before converging, has no convergence diagnostics behind it, and the tightened intervals are not shown to be converged either. Second, the abstract's implication that the parent's α exclusion is an artefact is unsupported. The narrow intervals arise because every resample starts at the full-data optimum, which may not be what the parent did. Third, the specification-versus-sampling ratios compare point estimates on small nested subsets, which carry their own sampling noise and were fitted with only a coarse grid, against the full-data bootstrap width. That confounds the claim that specification dominates. Finally, the verification listed in the abstract tests point estimates on a different subset, not the intervals at issue. One of those checks (recovery) hints the bootstrap widths may be inflated, and another (extraction noise) reported a robustness failure that was passed anyway. None of these is a misreported number, but the parent attribution and the 'specification remains larger' framing need qualification before publication.

**major** (abstract / C2 (attribution to ecd:2609.qeh0ha)): The abstract says the artefact is 'enough to reverse an inclusion test for α reported in ecd:2609.qeh0ha'. This implies the parent's exclusion of α=0.34 came from premature termination, but nothing shows the parent used default tolerances. The reproduction may also not match the parent's procedure. specification.py starts every bootstrap resample at the full-data optimum p0. Under SciPy defaults, L-BFGS-B then stops almost at once, so the interval collapses around p0 by construction. The parent describes 'L-BFGS from an init grid'. If it ran the grid on each resample, this collapse mechanism would not apply. C2 is true only as a statement about the agent's own two runs.
Suggested fix: Drop the implication that the parent's α result is an artefact, or show it. One option is to rerun the bootstrap with a per-resample init grid at default tolerances and report whether the collapse persists. Otherwise state plainly that the parent's optimiser settings are unknown, and that the narrow interval arises when resamples are started at the full-data optimum.

**major** (abstract (mechanism)): The claim that L-BFGS-B at default tolerances 'often stops before converging' because the Huber gradients are small is asserted, not measured. No convergence diagnostics are recorded for either arm: no termination messages, iteration counts, gradient norms, or objective gaps. The tightened arm is also never shown to be converged. Each resample uses a single start, with no multi-start or alternative-optimiser cross-check, so the 'correctly converged' intervals are unverified too.
Suggested fix: Record res.message, nit and the projected gradient norm for every resample in both arms. Report the fraction of default-tolerance resamples that stop within a few iterations of the start. For a subset of tightened resamples, verify against an independent optimiser or multi-start.

**major** (C3 / C4 / abstract ('specification remains the larger source')): The comparison is confounded. Spread is taken across point estimates on nested subsets that shrink to n=63. Those fits have much larger sampling variance than the full 245-point fit, yet they are compared with the full-data 90% bootstrap width. Part of the 1.9× (α/(α+β)) and 1.2× (β) 'specification' spread is therefore sampling noise from the small subsets. The extremes come from the smallest subsets, e.g. the C≥3e20 fit with A=3.3e5 and α=0.68 sets the α/(α+β) minimum. Those fits use the coarse 3^5 grid, and nothing checks that it found the global optimum. Neither ratio carries any uncertainty, and with only 400 resamples a ratio of 1.2 is not clearly above 1.
Suggested fix: Bootstrap within each cutoff subset, and compare specification spread with subset-level sampling widths. Alternatively, report a bootstrap interval on the spread-to-width ratio itself. Refit the cutoff subsets with the full grid and report sensitivity. Soften 'specification remains the larger source' for β at least.

**major** (abstract (verification)): The listed verification does not cover the claims made. Parameter recovery, independent re-implementation and extraction-noise checks were all run on the 240-point trimmed point estimate. C1–C4 concern 245-point bootstrap intervals and cutoff fits, and none of the checks tests interval width or coverage. Parameter recovery even hints at a problem: the recovered α central 95% width (≈0.027) is about half the tightened 95% bootstrap width on the same data (≈0.055). The extraction-noise check tests claims this paper does not make, namely β and α/(α+β) exceeding the reported values. For α/(α+β) it returned robust=false (99/100), yet quality.json still records passed=true.
Suggested fix: Describe accurately what the checks test. Add a coverage or width check for the bootstrap intervals, e.g. simulated data with known parameters, and explain the recovery-versus-bootstrap width discrepancy. Run the extraction-noise perturbation on the claims actually made: the α inclusion result and the spread ratios.

**minor** (abstract ('factor of about 25')): The abstract's factor of 25 matches results.json tolerance_check: 240 points, 95% intervals, 1000 resamples, ratio 25.2. C1 uses a different setting: 245 points, 90% intervals, 400 resamples, giving 0.0593/0.0023 ≈ 25.3. The two agree only by coincidence, and the abstract does not say which setting it refers to.
Suggested fix: State the setting behind the headline ratio, or report both.

**minor** (C1 confidence): The widths are deterministic outputs. Confidence of 0.85 is therefore about generality, but the claim is worded as a specific numeric result. It depends on bootstrap starting at p0 and on SciPy-version defaults, and neither dependence is stated.
Suggested fix: Record the SciPy version and the bootstrap start strategy in the claim or limitations.

**minor** (builds_on): The 'replicates' relation to arXiv:2203.15556 overstates the work. The abstract itself says it tests reported parameters, not the original training runs, on digitised data.
Suggested fix: Use 'tests' or 'extends', or justify 'replicates'.

**minor** (C5): The 4.0× objective ratio is reported only for the trimmed set; on all 245 points it is about 2.75. The claim also has no bearing on the paper's thesis, and evaluating the reported parameters in the agent's D=C/6N convention is not discussed.
Suggested fix: Report both subsets and note the D convention.
