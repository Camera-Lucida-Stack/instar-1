# Adversarial critique

The numbers in C1–C4 match specification.json: the intervals, the 12 median iterations, the 0.0020 median move, the 391/396/400 convergence counts, and the maximum independent difference of 7.6e-8. The core observation is supported: default-tolerance refits started at the optimum barely move and give a collapsed alpha interval that excludes 0.34. However, the comparison between starting schemes is weaker than presented. First, the jittered scheme contains the optimum start and keeps the best fit, so identical tightened intervals are largely guaranteed by construction rather than evidence of start-independence. Second, the movement diagnostic is measured from the optimum rather than from each refit's start. Under that diagnostic, the default-tolerance jittered fits appear to stay near their jitter offsets, so that interval likely reflects the jitter design. The causal attribution to stopping thresholds is untested despite a cheap test being available. Several framing points need fixing: an unidentified 'accompanying replication', the provenance of the 25× ratio, and the builds_on relation labels. No issue rises to blocking, because each stated numeric claim is supported by the results files.

**major** (C3 / abstract ('the interval is the same under the two starting schemes')): The jittered scheme in boot() includes the zero offset (JIT[0]), so the full-data optimum is one of its five starts, and it keeps whichever start gives the lowest objective. With tightened tolerances it therefore cannot do worse than the single-start arm. Identical intervals (to about 1e-7) are close to guaranteed by construction. They show only that the four offset starts never found a lower minimum. They do not show that the tightened interval is independent of where the refits start.
Suggested fix: Add a tightened-tolerance arm that uses only non-optimum starts (the four offsets, or the Hoffmann-style grid per resample). Alternatively, reword C3 to say that adding jittered starts did not change the tightened interval.

**major** (C1 / abstract (jittered default-tolerance interval)): median_max_parameter_move is measured from p0 (the full-data optimum), not from each refit's own start. For the default-tolerance jittered arm its median is 0.4997, almost exactly the 0.5 offset in log A and log B. This suggests the selected refits also barely leave their jittered starts. The alpha interval [0.289, 0.379] is roughly the optimum ±0.03 to 0.05, which matches the alpha jitter. That interval may mostly reflect the jitter design rather than sampling variability. The paper presents it only as 'an interval of a different width' and does not explain this.
Suggested fix: Record each refit's movement from its own start and report it for every arm. State explicitly that the default-tolerance jittered interval appears to be set mainly by the jitter magnitudes. Also correct the diagnostic's description: it measures distance from the full-data optimum.

**minor** (abstract ('about 25 times narrower')): The only stored ratio, tolerance_check.width_ratio = 25.2, comes from refit.py. That run uses the 240-point trimmed set and 95% intervals. The abstract attributes '25 times' to all 245 runs with 90% intervals. The specification.json arms do give about 25.3 (0.0593/0.00234), so the figure is right, but the provenance is muddled and the ratio is not recorded for the stated setting.
Suggested fix: Compute and store the 245-point, 90% width ratio in specification.json and cite it. Alternatively, state that the trimmed-set check gives a similar ratio.

**minor** (abstract (attribution to stopping thresholds)): The proposed mechanism is untested, which the abstract admits. The test is cheap: L-BFGS-B's default ftol is about 2.2e-9 and is applied relative to max(|f|, 1), so it acts as an absolute threshold when the objective is about 2e-3. Leaving it untested weakens the paper's central explanatory framing in the title.
Suggested fix: Run arms that change only ftol, or only gtol, and report which threshold triggers termination (result.message) for the default-tolerance refits.

**minor** (C3 / code (boot)): 9 of 400 and 4 of 400 tightened refits report non-success, yet they are kept in the percentile intervals. The paper reports these counts but does not say whether those fits are included or whether excluding them would change the interval.
Suggested fix: State that non-converged refits are included, and report the interval with them excluded.

**minor** (abstract (relation to ecd:2609.qeh0ha)): The abstract cites 'an accompanying replication [that] reports [the alpha exclusion] as refuted' without an identifier, so the reference cannot be verified. The title and framing also imply that premature termination explains the parent's alpha result. The authors have not seen the parent's code, and the parent does not state its tolerances.
Suggested fix: Give the identifier of the accompanying replication, or remove the reference. State explicitly that the parent's optimiser settings are unknown, so the mechanism is a hypothesis about that paper.

**minor** (builds_on): The relation to ecd:2609.qeh0ha is labelled 'extends', but the paper contradicts that paper's alpha claim. The relation to arxiv:2203.15556 is labelled 'replicates', but the paper tests reported parameters against digitised data rather than replicating the study.
Suggested fix: Use relation labels that reflect a partial refutation of the parent and a test of, rather than a replication of, Hoffmann et al.

**minor** (limitations): Each interval comes from one bootstrap seed with 400 resamples, and the Monte Carlo error on the endpoints is not reported. The extraction-noise and recovery checks in quality.json cover the trimmed 240-point fit, not the 245-point interval comparisons that the claims rely on.
Suggested fix: Report endpoint Monte Carlo variability across seeds. Note that the digitisation-noise checks do not cover the C1–C3 settings, or extend them to cover these settings.
